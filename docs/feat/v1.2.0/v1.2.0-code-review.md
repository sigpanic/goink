## 二、字段名一致性核对（commit a3d7b33）

a3d7b33 "refactor: rename chapter reference fields" 重命名了 4 个字段：

| entity struct | 旧名 | 新名 | 类型变化 |
|---|---|---|---|
| timeline.TimelineEntry | source_chapter_id | source_chapter | int64 → int |
| timeline.TimelineEntry | resolved_chapter_id | resolved_chapter | int64 → int |
| writing.WritingLog | chapter_id | chapter_number | int64 → int |
| character.CharacterRelation | chapter_id | chapter_number | int64 → int |

**核对结论**：所有 10 个 update 工具的 Args json tag 与 entity json tag 逐一核对**完全一致**，Unmarshal 路径正常工作。旧字段名在 mcp_tools + entity 包内已无残留。**重命名未引入字段名不一致 bug。**

详见 update 工具 Args ↔ entity 字段一致性核对表：

| 工具 | Args struct | entity struct | 不一致字段 |
|---|---|---|---|
| update_timeline_entry | UpdateTimelineEntryArgs | timeline.TimelineEntry | 无 |
| update_location | UpdateLocationArgs | location.Location | 无 |
| update_location_relation | UpdateLocationRelationArgs | location.LocationRelation | 无 |
| update_reader_perspective_entry | UpdateReaderPerspectiveEntryArgs | reader.ReaderPerspective | 无 |
| update_preference | UpdatePreferenceArgs | novel.PreferenceItem | 无 |
| update_character | UpdateCharacterArgs | character.Character | 无 |
| update_character_relationship | UpdateCharacterRelationshipArgs | character.CharacterRelation | 无 |
| update_story_arc | UpdateStoryArcArgs | storyarc.StoryArc | 无 |
| update_arc_node | UpdateArcNodeArgs | storyarc.ArcNode | 无 |

注：Args 的 finder 字段（entry_id/character_id/arc_id 等）json tag 与 entity PK `id` 不同名，这是 [rules.md:121](file:///home/nianhe/projects/todo/internal/mcp_tools/rules.md) 明确设计的——让 LLM 看到 finder 名字，同时 Unmarshal 不会动 entity.ID。

## 三、严重问题（1 项）

### 3.1 SlashMenu 与 ChatInput 过滤列表不一致导致选中错项

- **位置**：[frontend/src/components/chat/SlashMenu.tsx:70-72](file:///home/nianhe/projects/todo/frontend/src/components/chat/SlashMenu.tsx) + [frontend/src/components/chat/ChatInput.tsx:38-42](file:///home/nianhe/projects/todo/frontend/src/components/chat/ChatInput.tsx)
- **状态**：✅ 已修复（用户自行修复）
- **描述**：ChatInput 用 `includes` 过滤保持原序，SlashMenu 内部又用 `score()` 排序。两份列表顺序不同，`selectedIndex` 共用导致索引错位。
- **数据流验证**：
  | 环节 | 列表 | 顺序 |
  |---|---|---|
  | ChatInput filteredItems | includes 过滤 | 原始顺序 |
  | SlashMenu filtered | score 排序 | 排序后 |
  | Enter 选中 | filteredItems[slashIndex] | 索引未排序 |
  | 高亮 | filtered[selectedIndex] | 索引排序后 |
- **反例**：slashItems=[A=always, B=auto, C=abandon]，输入 `/a`：高亮 B(auto) 但 Enter 选中 A(always)
- **附带发现**：SlashMenu 的 `charMatch`（子序列匹配）比 ChatInput 的 `includes` 更宽松，两份列表项数都可能不同
