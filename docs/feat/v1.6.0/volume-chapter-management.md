# 卷与章节一体化管理

> 本文档描述 v1.6.0 在已有稳定章节 ID 与分卷数据模型之上，新增的用户可见结构管理能力；不描述具体代码实现。

## 目标

将卷管理与章节管理放在同一个独立的“章节管理”Tab 中。卷是章节的分组和阅读顺序的一部分，用户应能在同一界面完成建卷、调卷、建章、插章、移动和删除章节；不再拆成两个入口或两个 Tab。

现有 SidePanel 的 `ChapterList` 保持为写作时的快速切章入口，不承担结构管理职责。

## 前提与边界

- 章节以稳定 `chapter_id` 作为引用，界面仅展示实时计算的 `reading_number`。
- 卷顺序和卷内章节顺序共同决定阅读顺序；未分卷章节始终排在最后。
- 卷和章节的结构操作仅由前端经 App API 发起；AI 不提供卷 CRUD、插章、移动或删除章节工具。
- AI 仍可借助 `chapters/new.md` 新建正文，且可读写已有卷纲；这与前端的结构管理通道独立。
- 删除章节前必须检查 timeline、story arc、reader perspective、character relation 的章节引用；writing log 保留历史孤儿引用，不阻塞删除。

## 单一 Tab 布局

“章节管理”作为 ActivityBar 的一个独立主区域。主区域由相互联动的两部分组成，而非嵌套的卷/章节子 Tab：

1. 顶部卷轨道：按阅读顺序展示卷标签，提供新建、重命名、删除和拖拽排序。
2. 下方章节列表：按卷分组展示章节，末尾固定显示“未分卷”组；每行显示实时章节号、标题、字数和操作菜单。

选择、移动或删除卷会立即反映在下方分组和章节号中。章节拖到卷标签或“未分卷”组时，移动到对应分组末尾。

工作区占据 ActivityBar 右侧的可用宽度；进入时隐藏写作侧栏和聊天栏，但保持聊天组件挂载，以免切换页面中断正在进行的会话。离开工作区后恢复原布局。

个人中心同样只隐藏聊天栏，保持聊天组件挂载和流式会话监听。前端卷查询及后续卷操作 hook 放在 `components/volume/`，卷与章节的组合界面放在 `components/chapter-management/`。

首个前端提交只实现入口和只读展示：卷轨道、按卷分组的章节列表、加载/失败/空状态。卷与章节数据按当前小说分别查询；章节展示号采用后端返回的 `reading_number`，不在前端重新编号。AI 创建或更新章节的文件变更事件应刷新列表。卷操作和章节结构操作在后续提交开放入口。

卷轨道在列表滚动时保持可见，点击卷标签可定位并展开对应分组。超过 30 章的分组默认收起；展开后若超过 100 章，再按每 100 章的阅读编号范围分段，按需展开章节行，避免长卷把后续卷推离视野。

## 卷操作

- `PlaceVolume` 是唯一的卷结构编排入口：可创建新卷，也可移动已有卷；两者都指定目标位置。
- 位置以 `BeforeVolumeID` 表达：提供锚点时放到该卷前；为空时追加到末尾。
- 创建时 `SourceVolumeID` 为空且必须提供名称；移动时提供 `SourceVolumeID` 且不能提供名称。锚点卷必须属于当前小说。
- 因此该 API 同时覆盖末尾创建、指定位置插入和卷标签拖拽排序；前端只传本次移动动作，不传重排后的完整 ID 数组。
- 重命名：同一小说内卷名必须唯一。
- 删除卷：仅当卷内没有章节时允许；有章节时提示用户先移动或删除章节。删除时同步清理可选的卷纲文件。
- 新建卷可选择插在指定卷前或追加到末尾；重命名和删除入口放在卷轨道。拖动卷到另一卷标签时置于目标卷前，拖到轨道末尾时追加；拖拽只提交源卷与锚点卷 ID。
- 卷操作成功后同步刷新卷列表与章节列表，确保分组顺序和实时章节号使用同一份最新数据。卷删除的前端空卷检查只作即时提示，后端仍在执行时重新校验。

## 章节操作

- `PlaceChapter` 是唯一的章节结构编排入口：可创建新章节，也可移动已有章节；两者都指定目标卷（或未分卷组）和目标组内位置。
- 位置以 `BeforeChapterID` 表达：提供锚点时放到该章节前；为空时追加到目标组末尾。前端的“放到某章后”换算为“放到其下一章前”，最后一章后则传空锚点。
- 创建时 `SourceChapterID` 为空且必须提供标题；移动时提供 `SourceChapterID` 且不能提供标题。锚点章节必须属于目标章节组。
- 因此该 API 同时覆盖指定卷创建、卷内拖拽排序、跨卷移动、移入空卷和移回未分卷组；后端在单一事务内调整源组和目标组的排序键。
- 前端创建空正文与 AI 经 `new.md` 创建正文/大纲时，均先在外层 DB 事务中创建记录取得稳定 ID，再写对应文件；写入失败会回滚记录及排序调整。
- 删除：用户确认后调用 `DeleteChapter`；若返回阻塞引用，则展示交叉引用清单且不删除。无阻塞引用时后端在一个外层 DB 事务内删除章节记录并清理正文、大纲，文件清理失败会回滚章节记录；提交后清理对应 RAG 数据。删除后其余章节的展示编号自然连续重算。

## App API 边界

前端需要卷的 `PlaceVolume`、重命名、删除、查询 API，以及章节的 `PlaceChapter` 和删除 API。`PlaceVolume` 的 `source_volume_id` 与 `before_volume_id`、`PlaceChapter` 的 `source_chapter_id`、`target_volume_id` 与 `before_chapter_id` 都使用稳定 ID；可空 `target_volume_id` 明确表示未分卷组，避免使用 0 作为哨兵值。

删除 API 的失败结果应能让前端展示引用类型和引用记录，而非只给出不可删除的通用提示。

## 验收标准

- 用户不离开“章节管理”Tab，即可完成卷和章节的全部结构操作。
- 卷重排、章节创建或移动、章节删除后，列表按正确阅读顺序展示连续编号。
- 交叉引用始终指向稳定章节 ID，不随展示编号变化。
- 有阻塞引用的章节不能被删除；有章节的卷不能被删除。
- 原有写作侧边栏切章、AI 新建章节及卷纲读写不受影响。
