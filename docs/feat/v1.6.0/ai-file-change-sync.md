# AI 与前端修改文件的同步及写入安全

## 总体目标

AI 在 Goink 内修改文件后，前端能及时看到最新内容和相关列表；前端的未保存输入不会被事件、异步读取或其他标签覆盖。前端和 AI 同时写入同一文件时，任何一方都不能静默覆盖另一方。关闭标签、保存失败和需要用户选择的覆盖操作，都必须有明确结果。

范围包括章节正文、章节大纲、卷纲、`goink.md`、小说级技能和用户级技能。先交付缓存失效，再分开处理编辑器保存、已打开标签、技能表单和其他写入入口。每个 commit 有独立的交付结果和验证重点。

## 已有基础与仍存在的问题

- `c107fcb` 已提交后端 `expected_content` 条件写入、MCP 同文件并发检查；章节的 `file:changed` 已在同步字数维护之后发送。前端编辑器尚未传入读取时的原文，其他写入入口也未全部采用条件写入。
- 当前未提交的第一步代码已在 Workspace 接收 `file:changed` 并失效相应缓存，同时移除了章节侧栏和章节管理页的纯缓存监听。`ContentPanel` 的监听仍承担已打开标签的刷新，留待后续提交处理。
- `ContentPanel` 只有一组待保存任务和定时器。切到另一文件后继续输入，会替换前一文件的待保存内容；同一文件的多次保存可同时在途。失焦会尝试立即保存，但关闭标签不等待保存结果。
- 当前 `ContentPanel` 收到 AI 事件会直接回填内容并清除 dirty；打开文件的异步读取也可能晚于事件返回。技能表单有独立的输入状态，保存期间继续输入或保存失败都可能导致稿件被旧结果清掉。
- 风格提取、模式提取通过通用内容保存写入技能文件；远程技能安装虽有同名确认界面，服务端仍直接覆盖目标文件。MCP 标题更新失败时的正文回退也可能覆盖更新的内容；审批期间章节或卷被删除后，写入可能重建孤儿文件。

## 行为约定

1. `file:changed` 只表示 Goink 内 AI 编辑成功；事件失效 React Query 缓存，已打开标签另行处理。全局 `staleTime` 保持不变。第 1 个 commit 移除侧栏和章节管理页纯缓存监听；`ContentPanel` 的监听先保留，待已打开标签同步完成后再收敛，避免其读取先于缓存失效。
2. 保存任务以实际文件为单位：小说内文件由小说 ID 和路径标识；用户级技能跨小说指向同一文件。同一文件最多一次写入在途，新输入排队为下一版。切换标签不取消其他文件的待保存任务；失焦可立即触发。关闭有未保存稿件的标签必须等待保存成功，失败则保留标签与输入。
3. 编辑器保存以最后一次读取或成功写入的内容作为基线。AI 变更后，干净标签显示新内容；脏稿保持原样并停止继续自动写入。冲突时用户可以确认读取磁盘版，或确认以本地版覆盖；覆盖确认期间若文件再次变化，仍须重新处理冲突。保存回调只能确认它实际保存的那一版。
4. 打开文件与事件、连续事件交错时，以较新的文件内容为准，过期读取不得回填。技能表单须遵守同样的稿件保留和冲突规则；保存失败不能退出编辑态或清除输入。
5. 生成技能和远程安装保留现有的“发现同名文件时由用户确认”语义；空文件也算已存在。用户确认不是无条件覆盖授权；确认后文件若又变化，应提示冲突并保留新内容。MCP 回退和章节／卷删除也须与同文件写入协调，不能用无条件回退或单次提前查询掩盖竞态。

## Commit 路线

下表只列每个 commit 交付什么；具体实现与测试方案由相应提交单独 review。

| # | 建议的 commit subject | 做什么 |
|---|---|---|
| 1 | `fix(frontend): centralize AI file cache invalidation` | AI 修改文件后，工作区统一失效文件内容和相关章节、技能缓存；移除侧栏与章节管理页的重复缓存监听。 |
| 2 | `fix(frontend): preserve pending saves across tabs` | 编辑器按文件完成待保存任务；切换标签、失焦、连续输入和关闭标签时保留尚未成功写入的稿件。 |
| 3 | `fix(frontend): resolve concurrent editor writes` | 前端保存与 AI 编辑同一文件时不再静默互相覆盖；冲突或 AI 事件不清掉本地脏稿，并提供明确的处理选择。 |
| 4 | `fix(frontend): synchronize open files after AI edits` | 已打开的干净文件显示 AI 最新内容，未保存稿件保持原样；打开过程及连续事件不回填旧内容，收敛编辑器中的重复缓存失效。 |
| 5 | `fix(frontend): protect skill form drafts` | 技能表单保存期间继续输入、切换页面、保存失败或收到 AI 修改时，稿件和编辑状态保持正确。 |
| 6 | `fix(frontend): protect generated skill saves` | 风格与模式提取保存同名技能时明确处理覆盖，并在文件变化时保留已有内容；刷新相关缓存。 |
| 7 | `fix(skill): protect remote skill installation` | 远程技能安装的同名确认在服务端也得到保证；确认后目标变化不会被安装结果覆盖，技能列表与内容随安装结果刷新。 |
| 8 | `fix(mcp): preserve newer content during title rollback` | AI 修改章节正文后若标题更新失败，回退不会覆盖期间产生的新内容，并向用户报告部分成功的结果。 |
| 9 | `fix(content): prevent writes to deleted chapter and volume files` | 审批期间或保存期间删除章节、卷后，前端与 AI 写入均不能重建失去记录的正文、大纲或卷纲。 |

## 验证重点与边界

- Commit 1：章节、章节大纲、卷纲、`goink.md`、两级技能路径；页面未挂载或标签未打开；不同小说隔离及用户级技能跨小说共享；同一事件不会让章节列表被多个局部监听重复刷新。
- Commit 2～4：不同标签待保存、同文件连续保存、失焦和关闭、保存失败、AI 与前端写入顺序、打开时恰好收到事件、连续事件和过期请求回填。重点做可控时序测试。
- Commit 5～7：技能表单保存中继续输入、错误后保留编辑态；生成或安装同名技能时的确认、确认后的再次变化和跨小说缓存。
- Commit 8～9：标题更新失败后的并发修改与部分成功提示；审批等待期间删除章节或卷，以及校验与写入之间的删除竞态。这两项是独立的后端用例，应分别验证。
- 本版本不监听其他进程或操作系统直接修改文件，不承诺进程崩溃后的未保存稿件恢复。外部修改及跨进程写入需要另行设计；不能仅依赖当前进程内的文件锁。
